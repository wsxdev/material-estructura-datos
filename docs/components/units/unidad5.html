1. Técnicas de Optimización

Memoización

Técnica de almacenar resultados previos para evitar recalcular subproblemas en programación dinámica y recursión.

Ejemplo: Fibonacci Optimizado

def fibonacci(n, memo={}):
    if n in memo:
        return memo[n]
    if n <= 1:
        return n
    
    memo[n] = fibonacci(n-1, memo) + fibonacci(n-2, memo)
    return memo[n]

# Sin memoización: O(2^n)
# Con memoización: O(n)

Beneficios:

  • Reduce complejidad de exponencial a polinomial
  • Evita cálculos redundantes
  • Especialmente útil en recursión

Ventanas Deslizantes (Sliding Window)

Técnica para resolver problemas de subarrays/subcadenas manteniendo una ventana de tamaño constante que se desplaza a través de la estructura.

Aplicaciones:

  • Máximo/mínimo en subarrays
  • Búsqueda de patrones
  • Problemas de contigüidad

Complejidad:

  • Tiempo: O(n) vs O(n²) con fuerza bruta
  • Espacio: O(1)
def max_subarray_suma(arr, k):
    # Calcular suma de primera ventana
    window_sum = sum(arr[:k])
    max_sum = window_sum
    
    # Deslizar ventana
    for i in range(k, len(arr)):
        window_sum = window_sum - arr[i-k] + arr[i]
        max_sum = max(max_sum, window_sum)
    
    return max_sum

Programación Dinámica

Resuelve problemas dividiéndolos en subproblemas, almacenando resultados y combinándolos para la solución final.

Características:

  • Óptima subestructura: soluciones óptimas de subproblemas
  • Subproblemas solapados: se repiten durante la resolución
  • Memoización o tabulación para evitar recálculos

Ejemplo: Problema de la Mochila (0/1 Knapsack)

def knapsack(capacidad, pesos, valores, n):
    dp = [[0] * (capacidad + 1) for _ in range(n + 1)]
    
    for i in range(1, n + 1):
        for w in range(1, capacidad + 1):
            if pesos[i-1] <= w:
                dp[i][w] = max(
                    valores[i-1] + dp[i-1][w-pesos[i-1]],
                    dp[i-1][w]
                )
            else:
                dp[i][w] = dp[i-1][w]
    
    return dp[n][capacidad]

Complejidad: O(n * capacidad)

Búsqueda Binaria Avanzada

Más allá de búsqueda simple, incluye búsqueda del primer/último elemento, búsqueda en predicados, y aplicaciones en optimización.

Variantes Útiles:

  • Primer Elemento: Buscar el primer >= objetivo
  • Último Elemento: Buscar el último <= objetivo
  • Predicado: Buscar transición de condición

Aplicación: Encontrar Primer Elemento >= Objetivo

def busqueda_primer_mayor(arr, objetivo):
    izquierda, derecha = 0, len(arr) - 1
    resultado = -1
    
    while izquierda <= derecha:
        medio = (izquierda + derecha) // 2
        if arr[medio] >= objetivo:
            resultado = medio
            derecha = medio - 1
        else:
            izquierda = medio + 1
    
    return resultado

2. Patrones Avanzados

Backtracking (Retroceso)

Técnica para explorar todas las posibles soluciones, retrocediendo cuando se alcanza un estado inválido.

Aplicaciones:

  • Problema de N-reinas
  • Sudoku y puzles
  • Generación de permutaciones
  • Búsqueda de rutas en laberintos

Patrón Básico:

def backtrack(camino, restricciones):
    # Caso base: solución completa
    if es_solucion(camino):
        guardar_resultado(camino)
        return
    
    # Explorar opciones
    for opcion in obtener_opciones(restricciones):
        if es_valida(opcion, camino):
            camino.append(opcion)
            backtrack(camino, restricciones)
            camino.pop()  # Retroceso

Greedy (Codicioso)

Algoritmo que toma decisiones locales óptimas en cada paso, esperando obtener una solución global óptima.

Cuándo Funciona:

  • Problema tiene propiedad de estructura óptima
  • Elección localmente óptima lleva a solución global

Ejemplo: Selección de Actividades

def actividades_maximas(actividades):
    # actividades = [(inicio, fin), ...]
    # Ordenar por tiempo de finalización
    actividades.sort(key=lambda x: x[1])
    
    seleccionadas = [actividades[0]]
    ultima_fin = actividades[0][1]
    
    for i in range(1, len(actividades)):
        if actividades[i][0] >= ultima_fin:
            seleccionadas.append(actividades[i])
            ultima_fin = actividades[i][1]
    
    return seleccionadas

Complejidad: O(n log n)

Divide y Conquista

Divide el problema en subproblemas menores, resuelve cada uno recursivamente, y combina las soluciones.

Pasos:

  1. Dividir: Partir el problema en subproblemas
  2. Conquistar: Resolver recursivamente
  3. Combinar: Integrar soluciones

Ejemplos:

  • Mergesort
  • Quicksort
  • Búsqueda binaria
  • Multiplicación de matrices (Strassen)

Grafos: Algoritmos Avanzados

Dijkstra - Camino Más Corto con Pesos Positivos

  • Complejidad: O((V + E) log V) con min-heap
  • Aplicaciones: Redes, GPS, routing

Floyd-Warshall - Todos los Pares

  • Complejidad: O(V³)
  • Ventaja: Maneja pesos negativos

Componentes Fuertemente Conexas (SCC)

  • Kosaraju o Tarjan
  • Aplicaciones: Análisis de dependencias, SCCs en redes sociales

3. Programación Competitiva

Conceptos Clave

Límites de Tiempo

Típicamente 1-2 segundos. ~10⁸ ops/seg

Memoria

256-512 MB. Optimizar estructuras

Complejidad Viable

O(n²) para n≤10⁴, O(n log n) para n≤10⁶

Estrategias de Solución

1. Análisis de Límites

Identifica los límites del problema para elegir la mejor estrategia:

  • n ≤ 20: Fuerza bruta, backtracking
  • n ≤ 1000: O(n²)
  • n ≤ 10⁵: O(n log n)
  • n ≤ 10⁶: O(n)

2. Búsqueda Exhaustiva

Para problemas pequeños, explora todas las soluciones posibles.

3. Construcción Greedy

Si el algoritmo greedy es correcto, es más rápido que otras técnicas.

4. Búsqueda Binaria en la Respuesta

Si puedes verificar rápidamente si cierta respuesta es válida, busca binariamente sobre el rango de respuestas.

5. Estructuras de Datos Eficientes

  • Hash tables para búsqueda O(1)
  • Heaps para encontrar mínimo/máximo
  • Union-Find para conectividad
  • Segment trees para queries sobre rangos

Errores Comunes y Cómo Evitarlos

Error Causa Solución
Time Limit Exceeded Algoritmo demasiado lento Analiza complejidad, usa estructuras más eficientes
Memory Limit Demasiada memoria asignada Usa tipos más pequeños, libera memoria no usada
Wrong Answer Lógica incorrecta Prueba con casos borde, casos pequeños
Runtime Error Acceso fuera de límites Verifica índices, arregla divisiones por cero
Precision Error Problemas con floats Usa epsilon en comparaciones, evita resta de números similares
